1. Criando um pacote/crate

Um crate é uma unidade de compilação do Rust. Com Cargo, você pode criar um projeto binário:

cargo new meu_projeto

Estrutura:

meu_projeto/
├── Cargo.toml
└── src/
    └── main.rs

Para criar especificamente uma biblioteca:

cargo new minha_biblioteca --lib

Que terá:

minha_biblioteca/
├── Cargo.toml
└── src/
    └── lib.rs

A relação importante é:

Package
   ↓
gerenciado pelo Cargo
   ↓
pode conter crates
   ↓
Binary Crate → main.rs
Library Crate → lib.rs
2. Buscando crate do GitHub

Uma dependência pode vir diretamente de um repositório Git.

No Cargo.toml:

[dependencies]
minha_lib = { git = "https://github.com/usuario/repositorio.git" }

Depois:

cargo build

O Cargo obtém a dependência e a inclui na resolução do projeto.

Também é possível especificar uma branch:

[dependencies]
minha_lib = {
    git = "https://github.com/usuario/repositorio.git",
    branch = "main"
}
3. Publicando no crates.io

O crates.io é o registro público de crates usado pelo ecossistema Cargo.

Um fluxo típico é:

Criar biblioteca
      ↓
Configurar Cargo.toml
      ↓
cargo check
      ↓
cargo test
      ↓
cargo package
      ↓
cargo publish

Antes de publicar, o Cargo.toml precisa ter os metadados necessários para publicação, e você precisa estar autenticado no serviço.

4. Organização de código em Namespacing

Rust organiza nomes principalmente através do sistema de módulos e caminhos.

Exemplo:

mod usuario {
    pub fn cadastrar() {
        println!("Cliente cadastrado!");
    }
}

mod produto {
    pub fn cadastrar() {
        println!("Produto cadastrado!");
    }
}

fn main() {
    usuario::cadastrar();
    produto::cadastrar();
}

Apesar de ambas as funções se chamarem:

cadastrar

elas possuem caminhos diferentes:

crate
├── usuario
│   └── cadastrar()
│
└── produto
    └── cadastrar()

Portanto:

usuario::cadastrar();
produto::cadastrar();

não entram em conflito.
