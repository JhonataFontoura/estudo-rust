Portanto você normalmente não precisa escrever lifetimes explicitamente.

5. Quando aparece 'a?

Veja esta função:

fn maior(
    x: &str,
    y: &str
) -> &str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

Aqui existe uma dúvida importante:

&str x ──┐
         │
         ├── qual referência
         │   será retornada?
         │
&str y ──┘

Pode ser:

x

ou:

y

O compilador precisa entender a relação entre o lifetime das entradas e o lifetime da referência retornada.

Podemos declarar:

fn maior<'a>(
    x: &'a str,
    y: &'a str
) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

Agora apareceu:

'a

Isso é um Lifetime Parameter.

6. Entendendo 'a

Primeiro declaramos:

<'a>

Depois usamos:

&'a str

Então:

fn maior<'a>(
    x: &'a str,
    y: &'a str
) -> &'a str

estabelece uma relação entre os lifetimes.

Uma forma útil de pensar nesse caso é:

x ───────┐
         │
         ├── lifetime compatível 'a
         │
y ───────┘
         │
         ▼
       retorno

Na prática, a referência retornada só poderá ser usada enquanto for válida em relação às referências de entrada envolvidas.

7. 'a não é o nome de uma variável

Isso:

'a

é uma sintaxe de lifetime.

Você pode encontrar:

'a
'b
'c

Exemplo:

fn exemplo<'a, 'b>(
    x: &'a str,
    y: &'b str,
) {
}

Aqui temos dois parâmetros de lifetime.

8. Lifetime + Struct

Lifetimes ficam muito importantes quando uma struct guarda uma referência.

Isso:

struct Pessoa {
    nome: &str,
}

precisa expressar por quanto tempo essa referência pode ser considerada válida.

Podemos escrever:

struct Pessoa<'a> {
    nome: &'a str,
}

Uso:

fn main() {
    let nome = String::from("Jhonata");

    let pessoa = Pessoa {
        nome: &nome,
    };

    println!("{}", pessoa.nome);
}

Temos:

nome: String
     │
     │ borrowing
     ▼
Pessoa
└── nome: &str

A Pessoa não é dona da String.

Ela guarda uma referência para os dados.

Por isso Rust precisa garantir:

String original continua válida
            ↓
enquanto a referência armazenada
na Pessoa estiver sendo usada
9. Struct evitando Dangling Reference

Imagine conceitualmente:

struct Pessoa<'a> {
    nome: &'a str,
}

Se tentássemos fazer uma Pessoa continuar sendo usada depois que o String referenciado morreu, Rust impediria.

A situação problemática seria:

String
"Jhonata"
    │
    │ &
    ▼
Pessoa.nome

String destruída
    X

Pessoa.nome
    │
    ▼
tentaria apontar para dado inválido

Isso seria uma dangling reference.

Rust verifica os lifetimes para impedir esse cenário em código seguro.

10. Lifetime + impl

Uma struct com lifetime:

struct Pessoa<'a> {
    nome: &'a str,
}

Pode possuir métodos:

impl<'a> Pessoa<'a> {
    fn mostrar(&self) {
        println!("{}", self.nome);
    }
}

Observe:

impl<'a> Pessoa<'a>

O lifetime precisa fazer parte da implementação genérica da struct.

Exemplo completo:

struct Pessoa<'a> {
    nome: &'a str,
}

impl<'a> Pessoa<'a> {
    fn mostrar(&self) {
        println!("{}", self.nome);
    }
}

fn main() {
    let nome = String::from("Jhonata");

    let pessoa = Pessoa {
        nome: &nome,
    };

    pessoa.mostrar();
}
11. Lifetime 'static

Existe um lifetime especial:

'static

Ele indica que uma referência pode ser válida durante toda a execução do programa.

O exemplo clássico são string literals:

let linguagem: &'static str = "Rust";

Porque string literals fazem parte do binário e seus dados ficam disponíveis durante toda a execução.

programa inicia
│
├─────────────────────────────┐
│         "Rust"              │
│                             │
└─────────────────────────────┘
                         programa termina

Mas cuidado:

'static

não significa simplesmente:

qualquer variável ficará viva para sempre.

12. Lifetimes + Borrow Checker

Agora podemos conectar vários assuntos que você já estudou:

Ownership
    │
    ▼
quem é dono do valor?
    │
    ▼
Borrowing
    │
    ▼
quem está emprestando?
    │
    ▼
References
    │
    ▼
por quanto tempo são válidas?
    │
    ▼
Lifetimes
    │
    ▼
Borrow Checker verifica
    │
    ▼
impede referências inválidas

Essa é uma das bases da segurança de memória do Rust.

Resumo para copiar e colar
LIFETIMES E DANGLING POINTERS — RUST

DANGLING POINTER / DANGLING REFERENCE

→ referência ou ponteiro que aponta para
  memória/dado que já não é válido.

Exemplo conceitualmente perigoso:

let referencia;

{
    let numero = 10;
    referencia = &numero;
}

println!("{}", referencia);

Rust NÃO permite isso.

Quando o bloco termina:

numero
↓
deixa de ser válido

referencia
↓
tentaria continuar apontando para numero

Isso criaria uma dangling reference.


=========================
LIFETIME
=========================

Lifetime
→ representa/restringe o período em que
  uma referência pode ser usada com segurança.

REGRA:

Uma referência não pode ser usada
além do período em que o dado
referenciado permanece válido.


LIFETIMES NORMALMENTE SÃO INFERIDOS.

Exemplo:

fn tamanho(texto: &String) -> usize {
    texto.len()
}


=========================
LIFETIME EXPLÍCITO
=========================

Sintaxe:

'a

Exemplo:

fn maior<'a>(
    x: &'a str,
    y: &'a str
) -> &'a str {

    if x.len() > y.len() {
        x
    } else {
        y
    }
}


<'a>
→ declara um parâmetro de lifetime.

&'a str
→ referência relacionada ao lifetime 'a.


IMPORTANTE:

'a NÃO mantém o valor vivo.

'a descreve uma relação de validade
entre referências para o compilador.


=========================
LIFETIME + STRUCT
=========================

struct Pessoa<'a> {
    nome: &'a str,
}

A struct guarda uma referência.

Rust precisa garantir que o dado
referenciado continue válido enquanto
essa referência estiver sendo usada.


Exemplo:

let nome = String::from("Jhonata");

let pessoa = Pessoa {
    nome: &nome,
};


RELAÇÃO:

nome: String
     │
     │ &
     ▼
Pessoa
└── nome: &'a str


=========================
LIFETIME + IMPL
=========================

struct Pessoa<'a> {
    nome: &'a str,
}

impl<'a> Pessoa<'a> {

    fn mostrar(&self) {
        println!("{}", self.nome);
    }

}


=========================
STATIC
=========================

'static
→ lifetime que pode durar por toda
  a execução do programa.

Exemplo:

let linguagem: &'static str = "Rust";


=========================
RELAÇÃO GERAL
=========================

Ownership
    ↓
Borrowing
    ↓
References
    ↓
Lifetimes
    ↓
Borrow Checker
    ↓
verifica validade das referências
    ↓
impede dangling references


FORMA PARA MEMORIZAR:

Ownership
= quem é dono?

Borrowing
= quem está emprestando?

Reference
= quem aponta/empresta acesso ao valor?

Lifetime
= por quanto tempo essa referência
  pode ser usada com segurança?

Dangling Reference
= referência apontando para dado
  que já deixou de ser válido.


RESUMO FINAL:

Lifetime
→ ajuda o compilador a verificar
  relações de validade entre referências.

'a
→ parâmetro de lifetime.

&'a T
→ referência a T associada ao lifetime 'a.

'static
→ referência que pode ser válida durante
  toda a execução do programa.

Rust usa Ownership + Borrowing +
Borrow Checker + Lifetimes para impedir
dangling references em código seguro.

fn ler_texto(mensagem: &str) -> String {
