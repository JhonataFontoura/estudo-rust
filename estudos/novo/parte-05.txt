└── usuario
    │

        └── validacao

Se você estiver dentro de validacao:

começa da raiz.

sobe para cadastro.

começa em validacao.

mod agrupado em arquivos — Rust

Quando o projeto cresce, podemos usar mod para dividir e agrupar módulos relacionados em arquivos e pastas.

Imagine um sistema com usuários. Em vez de colocar cadastro, login e perfil no main.rs, podemos organizar assim:

src/
├── main.rs
├── usuario.rs
│
└── usuario/
    ├── cadastro.rs
    ├── login.rs
    └── perfil.rs

A hierarquia lógica fica:

crate
│
└── usuario
    ├── cadastro
    ├── login
    └── perfil
1. main.rs

Primeiro declaramos o módulo principal:

mod usuario;

fn main() {
    usuario::cadastro::cadastrar();
    usuario::login::entrar();
}

Quando Rust encontra:

mod usuario;

ele pode encontrar esse módulo em:

src/usuario.rs
2. usuario.rs agrupa os submódulos

Dentro de usuario.rs:

pub mod cadastro;
pub mod login;
pub mod perfil;

Esse arquivo funciona como o módulo usuario e declara seus submódulos.

A relação é:

usuario.rs
│
├── pub mod cadastro;
│        ↓
│   usuario/cadastro.rs
│
├── pub mod login;
│        ↓
│   usuario/login.rs
│
└── pub mod perfil;
         ↓
    usuario/perfil.rs
3. Arquivo cadastro.rs
pub fn cadastrar() {
    println!("Usuário cadastrado!");
}
4. Arquivo login.rs
pub fn entrar() {
    println!("Login realizado!");
}
5. Arquivo perfil.rs
pub fn mostrar_perfil() {
    println!("Exibindo perfil...");
}

Agora podemos acessar:

usuario::cadastro::cadastrar();

O caminho é:

usuario
    ↓
cadastro
    ↓
cadastrar()
Usando use crate

Também podemos importar essas funções:

mod usuario;

use crate::usuario::cadastro::cadastrar;
use crate::usuario::login::entrar;

fn main() {
    cadastrar();
    entrar();
}

Temos:

crate
│
└── usuario
    │
    ├── cadastro
    │      └── cadastrar()
    │
    └── login
           └── entrar()
Agrupando imports

Se vários itens vêm do mesmo módulo, também podemos agrupar o use.

Em vez de:

use crate::usuario::cadastro::cadastrar;
use crate::usuario::login::entrar;
use crate::usuario::perfil::mostrar_perfil;

podemos escrever:

use crate::usuario::{
    cadastro::cadastrar,
    login::entrar,
    perfil::mostrar_perfil,
};

E então:

fn main() {
    cadastrar();
    entrar();
    mostrar_perfil();
}

Isso é agrupamento de caminhos de importação, enquanto mod está organizando os módulos.

Outra estrutura: mod.rs

Você também pode encontrar:

src/
├── main.rs
│
└── usuario/
    ├── mod.rs
    ├── cadastro.rs
    ├── login.rs
    └── perfil.rs

Dentro de:

usuario/mod.rs

teríamos:

pub mod cadastro;
pub mod login;
pub mod perfil;

E no main.rs:

mod usuario;

As duas organizações representam conceitualmente:

usuario
├── cadastro
├── login
└── perfil

Para projetos novos, a organização com usuario.rs + pasta usuario/ costuma deixar a hierarquia explícita sem depender de vários arquivos chamados mod.rs.

mod com arquivos separados em Rust

Quando você quer dividir seu código em arquivos diferentes, mod permite dizer ao Rust que determinado arquivo faz parte da estrutura de módulos do projeto.

Exemplo simples

Estrutura:

src/
├── main.rs
├── usuario.rs
└── banco.rs
main.rs
mod usuario;
mod banco;

fn main() {
    usuario::mostrar_usuario();
    banco::conectar();
}

Aqui:

mod usuario;

declara o módulo usuario.

E:

mod banco;

declara o módulo banco.

O Rust procura os arquivos correspondentes:

mod usuario; → src/usuario.rs
mod banco;   → src/banco.rs
usuario.rs
pub fn mostrar_usuario() {
    println!("Usuário: Jhonata");
}
banco.rs
pub fn conectar() {
    println!("Conectando ao banco...");
}

O pub é necessário porque queremos acessar essas funções a partir de outro módulo.

Usando use crate

Também podemos importar as funções no main.rs:

mod usuario;
mod banco;

use crate::usuario::mostrar_usuario;
use crate::banco::conectar;

fn main() {
    mostrar_usuario();
    conectar();
}

A estrutura lógica fica:

crate
│
├── usuario
│      └── mostrar_usuario()
│
└── banco
       └── conectar()
Exemplo com três arquivos
src/
├── main.rs
├── usuario.rs
├── produto.rs
└── banco.rs
usuario.rs
pub fn cadastrar() {
    println!("Usuário cadastrado.");
}
produto.rs
pub fn cadastrar() {
    println!("Produto cadastrado.");
}
banco.rs
pub fn conectar() {
    println!("Banco conectado.");
}
main.rs
mod usuario;
mod produto;
mod banco;

fn main() {
    usuario::cadastrar();
    produto::cadastrar();
    banco::conectar();
}

Observe que existem duas funções chamadas:

cadastrar()

Mas não existe conflito quando usamos seus caminhos completos:

usuario::cadastrar();
produto::cadastrar();

Porque são módulos diferentes.

mod não é use

Essa diferença é muito importante:

mod
↓
declara/define que um módulo existe

use
↓
traz um caminho existente para o escopo atual

Por exemplo:

mod usuario;

use crate::usuario::cadastrar;

Primeiro:

mod usuario;

faz o módulo usuario fazer parte da árvore de módulos.

Depois:

use crate::usuario::cadastrar;

traz cadastrar para o escopo atual.

Assim podemos fazer:

cadastrar();

em vez de:

usuario::cadastrar();

mod declarando diretamente pelo path — Rust

Rust permite indicar manualmente qual arquivo será usado por um módulo através do atributo:

#[path = "caminho/arquivo.rs"]
mod nome_modulo;

Isso é útil quando o arquivo não está no local/nome padrão que o Rust esperaria.

Exemplo simples

Estrutura:

src/
├── main.rs
└── arquivos/
    └── usuario.rs

No main.rs:

#[path = "arquivos/usuario.rs"]
mod usuario;

fn main() {
    usuario::mostrar();
}

No arquivos/usuario.rs:

pub fn mostrar() {
    println!("Usuário: Jhonata");
}

A linha:

#[path = "arquivos/usuario.rs"]
mod usuario;

significa:

#[path = "arquivos/usuario.rs"]
          │
          └── arquivo que contém o módulo
                         ↓
                    mod usuario
                         ↓
              nome do módulo no código

Ou seja, o arquivo se chama:

arquivos/usuario.rs

mas dentro do programa ele será tratado como:

usuario

Por isso:

usuario::mostrar();
O nome do módulo pode ser diferente do arquivo

Você poderia fazer:

#[path = "arquivos/usuario.rs"]
mod cliente;

Mesmo o arquivo sendo:

usuario.rs

no código o módulo será:

cliente

Então:

fn main() {
    cliente::mostrar();
}
Exemplo com vários arquivos

Estrutura:

src/
├── main.rs
└── modulos/
    ├── usuario.rs
    ├── produto.rs
    └── banco.rs

main.rs:

#[path = "modulos/usuario.rs"]
mod usuario;

#[path = "modulos/produto.rs"]
mod produto;

#[path = "modulos/banco.rs"]
mod banco;

fn main() {
    usuario::cadastrar();
    produto::listar();
    banco::conectar();
}

usuario.rs:

pub fn cadastrar() {
    println!("Usuário cadastrado!");
}

produto.rs:

pub fn listar() {
    println!("Listando produtos...");
}

banco.rs:

pub fn conectar() {
    println!("Banco conectado!");
}

A relação fica:

main.rs
│
├── #[path = "modulos/usuario.rs"]
│       └── mod usuario;
│
├── #[path = "modulos/produto.rs"]
│       └── mod produto;
│
└── #[path = "modulos/banco.rs"]
        └── mod banco;
Sem #[path] × com #[path]

Normalmente:

mod usuario;

Rust procura o módulo seguindo as convenções de módulos, como o arquivo correspondente usuario.rs.

Com:

#[path = "outro_local/usuario.rs"]
mod usuario;

você está dizendo explicitamente:

Use este arquivo como código do módulo usuario.
