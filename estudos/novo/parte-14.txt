6. Criando formulário de cadastro

Podemos criar um formulário HTML:

<form action="/usuarios" method="post">

    <input
        type="text"
        name="nome"
        placeholder="Nome"
    >

    <input
        type="email"
        name="email"
        placeholder="E-mail"
    >

    <button type="submit">
        Cadastrar
    </button>

</form>

No Rust, podemos representar os dados:

use rocket::form::FromForm;

#[derive(FromForm)]
struct UsuarioForm {
    nome: String,
    email: String,
}

A rota recebe:

use rocket::form::Form;

#[post("/usuarios", data = "<form>")]
fn cadastrar(
    form: Form<UsuarioForm>
) -> String {
    format!(
        "Usuário cadastrado: {}",
        form.nome
    )
}

Fluxo:

Form HTML
   ↓
POST
   ↓
Form<UsuarioForm>
   ↓
Controller
   ↓
Cadastro
7. Outra maneira de carregar módulos

Além de declarar:

mod controllers;

e depois acessar caminhos completos, podemos importar itens para facilitar seu uso.

Por exemplo:

mod controllers;

use controllers::usuario_controller;

Depois:

usuario_controller::index

Ou importar diretamente:

use controllers::usuario_controller::index;

Permitindo:

routes![index]

Isso se conecta ao que você estudou anteriormente:

mod
→ declara/carrega módulo

use
→ traz um caminho para o escopo

crate
→ raiz da crate

super
→ módulo pai

self
→ módulo atual
8. POST Form e FlashMessage

Depois que um formulário é enviado, muitas aplicações precisam mostrar uma mensagem:

Usuário cadastrado com sucesso!

Uma abordagem comum é:

POST
 ↓
processa formulário
 ↓
salva dados
 ↓
redirect
 ↓
GET
 ↓
mensagem de sucesso

Isso também evita problemas de reenvio de formulário ao atualizar a página.

Conceitualmente:

#[post("/usuarios", data = "<form>")]
fn cadastrar(form: Form<UsuarioForm>) {
    // valida
    // salva
    // adiciona mensagem
    // redireciona
}

As APIs exatas para mensagens flash dependem da abordagem/versão usada no projeto, mas o conceito central do tópico é associar uma mensagem temporária ao redirecionamento após uma operação.

9. Fluxo de alteração de dados

Para atualizar um usuário, normalmente temos duas etapas.

Primeiro:

GET /usuarios/10/editar

Mostra o formulário preenchido.

Depois:

POST/PUT /usuarios/10

envia os novos dados.

Exemplo conceitual:

#[get("/usuarios/<id>/editar")]
fn editar(id: u32) -> Template {
    // buscar usuário
    // carregar formulário
    todo!()
}

Depois:

#[post("/usuarios/<id>", data = "<form>")]
fn atualizar(
    id: u32,
    form: Form<UsuarioForm>,
) {
    // validar
    // atualizar
}

Fluxo completo:

Usuário
   ↓
Editar
   ↓
GET /usuarios/10/editar
   ↓
Busca usuário
   ↓
Mostra formulário
   ↓
Usuário altera dados
   ↓
POST
   ↓
Atualiza
   ↓
Redirect
   ↓
Página atualizada
10. Fluxo de exclusão

A exclusão normalmente recebe o identificador do recurso.

Exemplo conceitual:

#[post("/usuarios/<id>/deletar")]
fn deletar(id: u32) {
    // localizar usuário
    // excluir usuário
    // redirecionar
}

Fluxo:

Usuário
   ↓
Excluir
   ↓
ID
   ↓
Controller
   ↓
Repository
   ↓
DELETE
   ↓
Banco
   ↓
Redirect

Em uma aplicação real, também é comum pedir confirmação antes:

Deseja realmente excluir?
